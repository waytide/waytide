# When an experiment's phase starts, its goal is stated, and the phases are listed with the current one marked

**Trigger:** When starting a phase of an experiment

**At the start of an experiment's phase, state the goal of the phase to the engineer, before its work.** The goal is what the phase is to establish, and how that serves the experiment's question.

**As the engineer stated it:** when starting an experiment's phase, state the goal of the phase.

**List the experiment's phases with it, in the order the record names them, and mark the current phase in the list.** The engineer then sees where the phase sits among the others, and which ones are done and which are still to come.

**As the engineer stated it:** also list the phases of the experiment, and indicate the current phase in that list.

**It is stated at each phase's start, and not only when the record is written.** The record names the phases and their order at the start of the experiment, and states each phase's forecast before its work. A phase can start many turns after the record was written, and the engineer then reads a branch switch and new work without the reason for either in front of them.

**Why:** a phase is a question of its own that serves the experiment's question, so its work is judged against that goal. Stated at the start, the goal is on screen when the engineer reads the phase's first work, and the work can be checked against it.

**How to apply:** when a phase starts, state its goal before its work, in the response that starts it. Say what the phase is to establish and how that serves the experiment's question. List the experiment's phases in the record's order, and mark the current one.
