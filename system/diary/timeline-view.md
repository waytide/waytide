# Timeline view: on request, list all experience log entries chronologically, each line led by its datetime

When the user asks for the timeline (e.g. "show the timeline", "list the entries"), list every experience log entry in the active user's log directory `users/<slug>/` (the `20*.md` files there, not `agent/log/` or `agent/rules/`), where `<slug>` is the active user resolved per [[identity-resolution-contract]], in chronological order, oldest first. Format each as a single bullet `- **<datetime>** — <title>`, where `<datetime>` is the human-readable datetime line under the entry's title (e.g. `Wed Jun 17 2026 at 18:28`) and `<title>` is the entry's `# ` heading with the leading `# ` stripped. End with a one-line count and date span (e.g. "15 entries, spanning Jun 15–17, 2026"). Output the list only — no preamble.

This count + date-span footer is **computed at display time only**; it is not stored anywhere. The materialized index (`TIMELINE.md`) holds the bullets alone.

The bullet list is also materialized to `users/<slug>/TIMELINE.md` (one index per user, in that user's directory), maintained by the "new entry" (ordered insert) and "reindex" (full rebuild) directives ([[new-entry-trigger-rebuilds-timeline-index]]). When asked to "show the timeline", still regenerate the view fresh from the entry files rather than echoing `TIMELINE.md`, so the displayed view is correct even if the materialized index is momentarily stale — and append the computed footer.

**Why:** The view is regenerated on demand from the entry files so it never drifts out of sync. A materialized `TIMELINE.md` is also kept for at-a-glance reference outside a session. Storing only the bullets (no footer) means adding an entry is a clean single-line insertion with nothing to recompute; the footer, the one part that changes on every addition, is derived when the timeline is shown. Keeping this as a rule rather than a `.claude/commands/` slash command keeps all agent artifacts under `agent/`.

**How to apply:** To show the timeline, resolve the active `<slug>` ([[identity-resolution-contract]]), read the `20*.md` files in `users/<slug>/`, sort by their datetime line, emit the bullets, and append the computed count + date-span footer. That user's `users/<slug>/TIMELINE.md` index stores those same bullets without the footer; see [[new-entry-trigger-rebuilds-timeline-index]] for how it is maintained.
