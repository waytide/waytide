# Loop record — The project mode: formal or creative

The design of a project-level mode, chosen at initiation, deciding whether a project's planning
artifacts are a **design** and a **plan** or an **aspiration** and an **intention**. The
feature's lifecycle record is `waytide/local/features/2026-08-05T06-02-05Z-project-mode.md`.

**Mode: attended.** Chosen at initiation on 2026-08-04 beside the working location. The loop
stops at every hinge and the developer deliberates each one, so every cycle below carries the
options put at the gate and the decision that resolved it.

## Cycle 1 — where the mode is recorded and what reads it

**Hinge.** The mode decides which directory every planning artifact goes in for the project's
life, so it has to be legible at the start of every session. Everything else in the feature rests
on this; the prompt itself is mechanical by comparison.

**A finding that shaped the options.** Inferring the mode from which directories exist is
**circular**: the first aspiration cannot be placed until the mode is known, and the directory
only exists once something is in it — and git does not track an empty directory. So inference
needs a placeholder file anyway, which makes it *a file exists* arrived at indirectly. That
reduced the real decision to whether the mode is **stated or inferred**, and if stated, whether
it lives in what the agent already reads or in something a script can parse.

**Options.** A local rule in `waytide/local/rules/`; a `**Mode:**` recognizable-content line in a
dedicated file under `waytide/local/`, in the form `session-start.sh` already parses; or the
presence of `waytide/local/aspiration/` itself.

**Decision.** **A local rule.** It introduces no mechanism: local rules are read unconditionally
at the start of every session, and the mode genuinely **is** a binding convention of the project
rather than a setting attached to one. It also puts the mode where the system already keeps
things of its kind, which the recognizable-content line would not have.

**What the choice gives up**, recorded rather than re-argued: the mode is not machine-readable,
so `session-start.sh` cannot report it in the notice without parsing prose. And changing mode
means removing a binding rule, which the rules-convention makes a deliberate act with
reconciliation attached — heavier than flipping a value, and arguably correct for a decision of
this reach.

## Cycle 2 — what an absent mode rule means, and when the prompt fires

**Hinge.** Forced by cycle 1, and one question wearing two faces. If absence means formal, then
choosing formal writes nothing and nothing distinguishes *asked and chose formal* from *never
asked*, so the prompt has no way to know it has already fired. If the rule is always written,
that is solved, but every project that already exists is prompted on its first session after the
rule ships.

**Options.** Always write the rule and prompt once when absent; absence means formal with the
prompt tied to the install; absence means formal with the prompt raised when the first planning
artifact is about to be written.

**Decision.** Absence means formal, with the prompt tied to the install.

**This cycle's outcome did not stand.** The developer identified a silent failure in it, and
cycle 3 replaced it. The cycle is kept as written because it happened, and because the defect is
only legible against the choice that had it.

## Cycle 3 — the silent revert

**Hinge.** Raised by the developer against cycle 2's outcome: if the mode is creative, a creative
mode rule is written, and that rule is then **accidentally deleted**, absence reads as formal —
and formal expects `design/` and `plans/`. The project keeps working, incorrectly, with nothing
announcing it: the agent writes to the formal directories while `aspiration/` and `intention/`
hold the project's actual planning artifacts, and the project's planning splits across two
vocabularies unremarked. It is the silent-failure class this system argues against everywhere
else.

**What the agent contributed.** That the observation identifies a **missing check** rather than
necessarily overturning cycle 2: the **directories are evidence**. A project holding
`local/aspiration/` with no creative rule is a **contradiction**, not a formal project, and that
is visible without any new mechanism. It is the same stance taken in the registry parser earlier
the same day — refuse to misread rather than proceed on ambiguous input. Also noted, in fairness
to the option the agent had not argued for: *always write the rule* degrades better on its own,
a deleted rule there producing a re-prompt, which is loud rather than silent.

**Options.** Corroborate against the directories while keeping absence-means-formal; always write
the rule **and** corroborate; always write the rule with no check.

**Decision.** **Always write the rule, and corroborate.** So:

- **Both modes write a mode rule** into `waytide/local/rules/`.
- **An absent rule means the question has never been asked**, not that the project is formal, so
  the agent asks — once.
- **The planning directories are checked against the rule.** `aspiration/` or `intention/` present
  with no creative rule, or a creative rule with only the formal directories populated, is a
  **contradiction**: the agent surfaces it and asks rather than assuming either mode.
- **The accepted cost** is the one cycle 2 had avoided: the four consuming projects in the
  registry and this repository are each prompted once, about a mode none of them is changing.

## Cycle 4 — what the two modes actually differ in

**Hinge.** Whether the creative mode gets its own conventions and document formats, or shares the
formal mode's. The source observation had named the **doubling cost** — four `foundation` rules
forked, every future rule naming these directories inheriting the obligation — as the risk that
might sink the whole idea.

**Decision, given as direction.** **The conventions and document formats are the same.** Also
settled in the same instruction: the mode **does not change after initiation** (to be considered
further later), and the mode rule is named **`formal-mode`** or **`creative-mode`**, stating that
the project operates under that mode and which conventions are active.

**What the agent surfaced, because it changes what the feature is.** The argument that made this
two modes rather than two names was **supersession** — *nobody supersedes an intention*, and an
aspiration is not measured by completion the way a plan is. **Identical conventions abandon that
claim.** An intention is superseded exactly as a plan is, carries the same checkbox tasks, and is
measured the same way. What differs is the vocabulary and the directory.

**That is the stronger position rather than a retreat, and the system's own rules say why.**
`language-is-precise-here` holds that a word is the thought's working surface and choosing a word
chooses a concept; `rules-install-a-mindset` holds that a large share of what a rule does is
install a **stance**, and that vocabulary is the most direct lever on a mental model. A developer
writing an *aspiration* is doing something different from one writing a *design*, and the
difference is in them rather than in the document. The mode is that lever at the scale of a
project. It is a different claim from the one the observation recorded, which is why the
observation is reconciled rather than left to read as though it predicted this.

**A mechanical note.** A local rule takes the ISO-8601-UTC filename prefix, so the file is
`2026-…Z-creative-mode.md` — the specified name is the name part. A useful consequence: the
**filename alone carries the mode**, so both the never-asked check and the corroboration work
without the file being opened.

## Cycle 5 — how the four conventions carry the mode

**Hinge.** `design-convention`, `plans-convention`, `design-document-format`, and
`plan-document-format` name `waytide/local/design/` and `waytide/local/plans/` throughout. With
the conventions shared, something still has to tell a creative project which directory it uses.

**Options.** The mode rule states the substitution once and the four are left untouched; each of
the four is edited to name both; or the four stop naming directories at all and speak of the
settled-direction and sequencing artifacts, with the mode rule binding those to paths.

**Decision.** **Edit the four to name both.** A reader of any one rule sees the truth for their
project without having to know the mode rule exists. The cost accepted is that the mode is now
stated in five places rather than one, and that a future rule naming these directories inherits
the same obligation.

**What was built.** The `a-project-works-in-formal-or-creative-mode` rule in `foundation`; both
directory conventions retitled and opened with the creative counterpart; both document formats
retitled and stating that the creative document's shape is the same shape entirely; and the
`foundation` README carrying the mode in its summary and in its work-artifact directory list.

Cycles follow as the design proceeds.
