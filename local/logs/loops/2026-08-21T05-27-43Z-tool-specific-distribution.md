# Loop record — Tool-Specific Distribution

The feature that takes a tool-named package out of Waytide's default distribution and ships it
through a distribution of its own. `code/ruby` is the case that exists. Ten cycles so far, three of
them the named hinges and seven of them structural decisions the hinges surfaced. Nothing is built
in this repository yet. The fifth cycle re-cradled the work, the sixth sent it out to another
repository, and the ninth found that the repository is the Ruby package rather than a
distribution.

**Mode: attended.** The engineer selected it at the feature's start, beside the working location.
The loop waits at every hinge.

## Cycle 1 — Actuation

- **Hinge** — what a Ruby project types to get Waytide plus Ruby. The unit is a distribution
  rather than a callable, so the use site is a consuming project's install block and the actuation
  is the command in it.
- **Options** — the language as an argument, `sh install-all.sh ruby`, against one repository and
  one script. A distribution repository, `waytide-ruby`, carrying its own `install-all.sh`, where
  the use site states the distribution by where it fetches from. A second script, `install-ruby.sh`
  beside the first, two fetches and two commands.
- **Decision** — the distribution repository. This settled the mechanism question *The Ruby package
  leaves the default distribution* had left open, and settled it as the third of the three
  candidates that idea named.

## Cycle 2 — Observation

- **Hinge** — which effect of the install the test reads.
- **Options** — the installed set, read from the package directories the run placed. The
  difference between the two distributions, read by installing both into separate scratch projects.
  What the engineer is told, read from `session-start.sh`'s notice.
- **Decision** — the installed set, after `Explain`. The explanation put the three against what a
  failure would mean in each: the installed set cannot catch the composite's installer still
  carrying `code/ruby`, the difference reads the feature's actual claim at the cost of two
  installs, and the notice couples the test to a second unit so a failure does not localize.

## Cycle 3 — Controls

- **Hinge** — what the known inputs are built from, given `WAYTIDE_ORIGIN` already lets an
  installer be exercised against local paths.
- **Options** — split repositories, each package split out of the composite into a bare
  repository. Minimal repositories, eight bare repositories each carrying one README. The
  published remotes, which is no control at all.
- **Decision** — split repositories, after `Explain`. The explanation named the question
  underneath: whether this feature's design turns on package content. It does not, and the split
  was taken anyway, so the controls carry more than the design strictly needs.

## Cycle 4 — Where `waytide-ruby`'s installer is authored

- **Hinge** — not one of the five. It was surfaced by assembling turn one, which needed a path to
  the unit under test and had none. `CONTRIBUTING.md` states that all authoring happens in the
  composite and that component repositories are downstream-only, generated by `git subtree split`
  from `system/<package>`. `waytide-ruby` is not a package, so it has no slot.
- **Options** — `distributions/ruby/`, a new top-level directory split-published the way a package
  is. A root-level script copied into `waytide-ruby` on publish. Authored in `waytide-ruby` itself,
  a stated exception to the composite-only rule.
- **Decision** — authored in `waytide-ruby` itself. That makes it a third kind of repository:
  neither the composite nor a component, since it receives no split. `report-direct-commits.sh`
  iterates `system/` package directories, so nothing here reaches it or checks it.

## Cycle 5 — Re-cradle

- **Hinge** — the cradle could no longer hold the unit. Turn one copies `waytide-ruby`'s installer
  into a scratch project, and cycle 4 put that file in a repository this one cannot reference.
  The dbe-human-in-the-loop rule sends the fix to the cradle rather than the implementation.
- **Options** — the composite's set, moving the actuation to the installer this repository owns.
  Both sets, with `waytide-ruby`'s installer carried among the controls. No test in this
  repository, the implementation hinge degenerate.
- **Decision** — both sets, `waytide-ruby`'s supplied as a control.

## Cycle 6 — Resolving cycles 4 and 5

- **Hinge** — the contradiction between them. Cycle 5's control is a copy of a file cycle 4 placed
  in another repository, and that file existed nowhere. Whatever was written first would have been
  the original rather than a copy.
- **Options** — cycle 4 gives, and the installer is authored here in `distributions/ruby/` and
  split-published. Cycle 5 gives, and the test reads the composite's set alone. Neither gives, and
  `waytide-ruby` is built first so there is something to copy.
- **Decision** — neither gives. `waytide/waytide-ruby` was created public, and its installer
  authored and pushed there. The engineer selected public over private-until-conclusion, having
  been told that a public repository with a working installer is installable while this feature is
  still open.

## Cycle 7 — How the distribution gets the base set

- **Hinge** — whether the distribution's installer restates the package set or composes on the
  composite's. The idea this feature realizes named it as unsettled, and named restating as a
  second place the set is asserted.
- **Options** — compose by fetching and running the composite's `install-all.sh`, then adding
  `code/ruby`. Restate, with its own eight `add` lines and the same bootstrap. Compose by bringing
  the composite's script in with `git subtree` so it is a tracked file rather than a run-time
  fetch.
- **Decision** — compose by fetching and delegating. The base set is asserted upstream and this
  script cannot drift from it.

## Cycle 8 — The installer's name

- **Hinge** — what a package's installer is called. Written as `install-all.sh`, which is the
  composite's name for the script that installs everything from its root.
- **Options** — none were put. The engineer stated it: `install.sh`, because this follows the
  component package conventions while sitting in an external repository.
- **Decision** — `install.sh`, as `system/foundation/install.sh` is. It also dissolved a collision
  the earlier name created: both scripts were `install-all.sh`, so fetching the base into the
  project root would have overwritten the running script while `sh` was reading it.

## Cycle 9 — It is a package, not a distribution

- **Hinge** — how the Ruby rules and the installer share one repository. Three options were put,
  each treating them as unlike things sharing a space.
- **Chat** — the engineer refused the framing and supplied the missing fact: **the dependency
  direction is `waytide-ruby → waytide`**. Installing the Ruby package installs the rest of
  Waytide, which is the ordinary package-dependency shape. Waytide already carries it, in
  `install-dependencies.sh`.
- **Decision** — the repository is the **Ruby package**, and the rules move into it from
  `system/code/ruby/`. `waytide/code-ruby` is retired. What is unusual is only the size of the
  dependency: every other package names one to three, and this one names the other seven. The
  distribution installer was a mechanism that already existed under another name.

## Cycle 10 — The installed location, and the repository name

- **Hinge** — where the package installs, and what follows for the repository's name.
- **Chat** — the engineer stated `tool/ruby-lang/`, then corrected it to `tools/ruby-lang/`, which
  also matches the house plural of `rules/`, `ideas/`, `logs/`, and `implementations/`.
- **The breakage this surfaced** — `refresh-packages.sh` line 95 derives a repository name by
  flattening the installed path, `tr '/' '-'`. A package at `tools/ruby-lang` is refreshed from
  `tools-ruby-lang.git`, and the repository was `waytide-ruby`. The correspondence the scheme rests
  on was gone.
- **Options** — `waytide/ruby-lang`, naming a grouped package's repository by its leaf and changing
  the derivation once. `waytide/tools-ruby-lang`, keeping the flattening exactly. Keep
  `waytide-ruby` and teach foundation to read a package's origin rather than derive it.
- **Decision** — `waytide/tools-ruby-lang`. Nothing in any script changes, and the repository was
  an hour old with no consumers, so the rename cost only the raw URLs in its own files.

## Outcome

**`waytide/tools-ruby-lang` exists, is public, and carries `install.sh`, `README.md`, and a
`LICENSE`.** Its raw install URL resolves, and `install.sh` places the package at
`waytide/system/tools/ruby-lang/` from that repository.

**The rules have not moved yet.** The migration record is written and no increment has run, so
`system/code/ruby/` is still here and still authoritative.

**SSH to GitHub was rate-limited throughout cycles 6 and 10**, after the eight-package publish
earlier in the session. The repository was created, cloned, renamed, and pushed over HTTPS — the
fallback kept when the addresses moved to SSH.
