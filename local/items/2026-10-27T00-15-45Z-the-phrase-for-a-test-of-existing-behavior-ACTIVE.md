# The phrase for a test of behavior that already exists

- **State:** Active
- **Tags:** [idea]

**A literal phrase is wanted for a test that passes without any implementation being written, because the behavior it checks already exists.** It replaces "green-on-arrival", which is figurative. The phrase now in the rules, "passes when first run", is not right either, the engineer said on 2026-10-26. It stands in the a-test-of-behavior-that-already-exists-is-coverage-not-design rule and the "TDD designs, coverage prevents" rule until one of the options is chosen.

**The options recorded so far:**
- passes as first written, the engineer's
- passes by default, the engineer's
- cannot fail, the engineer's
- fail proof, the engineer's
- uncontested, which the engineer judged good on 2026-10-26, on condition that it is explained
- a test of existing behavior, the phrase the rule's title uses
- a test the existing code already satisfies
- a test that passes before any implementation is written
- passes when first run, the phrase now in the rules, judged not right

**"Confirming test" is the taxonomic term, and it is kept.** The engineer said on 2026-10-26 that, taxonomically, such a test is a confirming test, and that the term is not to be lost. It is not yet settled as the phrase for this purpose.

**"Uncontested" needs its explanation stated wherever it is used.** The engineer took it from a no-bid contract, which is awarded without a competing bid. A draft of the explanation: *an uncontested test passes without any implementation being written to meet it, because the behavior it checks already exists. In DBE, a test is contested when it fails until code is written to satisfy it.* The word is figurative, so it would be reserved with that meaning rather than used unexplained.
