# A Generalized Description of Waytide — Aspiration

- **State:** Deferred
- **Tags:** [aspiration]

## Premise

**Waytide has one description of itself, general enough to serve both the README and the
website.** Not two written separately for two audiences, and not one written for one and cut down
for the other.

## Background & Motivation

**Both surfaces need a description today and only one has anything.** The root `README.md` opens
with *reusable agent directives — the rules an AI coding agent reads at the start of a session —
organized into installable packages*, written by hand. The website has **no public explanation at
all**: its drafts were removed on 2026-07-30, which the *Waytide's Self-Explanation* aspiration
records.

**A description written twice drifts, and the drift is already evidenced here.** Three package
`README.md` files were corrected by hand in a single session because the rules had moved
underneath them. That is the same failure this aspiration exists to keep off a description of the
whole system, where it is more expensive: a package README is read by someone who already has the
package, and the general description is read by someone deciding whether to look at all.

**The two surfaces read differently, which is what makes this hard.** The README is met on GitHub
by a reader who has arrived at a repository and wants to know what it is. The website is met by a
reader who arrived at a claim. One is reached from inside the artifact and one from outside it, and
a description that ignores the difference will serve one of them badly.

## Its relationship to the self-explanation aspiration

**That aspiration settles that Waytide explains itself through two surfaces — an interactive chat
and the website — both driven from one source.** This one is not a competing arrangement. It names
a **third surface**, the README, and asks the same question of it: whether one description can
serve it too.

**What that aspiration left in the `website` project is production and presentation.** Where a
generalized description is produced from, and how each surface renders it, belongs there rather
than here. This aspiration holds the direction: that there is **one** description.

## What "generalized" has to mean

**Open, and stated here so it is not decided by accident.** The word is doing real work and has at
least two readings that lead to different artifacts:

1. **One text, rendered in both places.** The same words appear in the README and on the website,
   and each surface frames them.
2. **One source, two renderings.** A description held once and produced into each surface at the
   length and framing that surface needs.

The second is what the self-explanation aspiration's **projection** already describes. Whether
this description is that projection, or something the projection is produced from, is not settled.

## Settled

- **2026-08-10** — **Waytide has one generalized description of itself, serving both the README
  and the website.** Nothing beyond this is settled.

## Out of Scope / Deferred

- **Which reading of "generalized" is taken**, and therefore whether the artifact is one text or
  one source.
- **What the description says.** Its content is not drafted here.
- **Where it lives**, and whether it is the projection the self-explanation aspiration names or an
  input to it. Production and presentation are the `website` project's, by that aspiration's own
  settlement.
- **Whether the package READMEs are reached.** This aspiration is about the description of the
  system as a whole. Whether the same arrangement should hold for each package's own README is a
  separate question, and the drift evidenced above came from those files.
- **The interactive chat**, which the self-explanation aspiration holds and this one does not
  reopen.
